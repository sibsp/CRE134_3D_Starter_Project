=H3 Moving around the Scene view

<b>Fly like a game camera</b>: Hold the <b>right mouse button</b>, then use <b>W A S D</b> (and Q / E for down / up). Hold Shift to go faster.

<b>Orbit around a point</b>: Hold <b>Alt</b> and drag with the <b>left mouse button</b>.

<b>Pan (slide sideways)</b>: Drag with the <b>middle mouse button</b>.

<b>Zoom</b>: Scroll the mouse wheel.

<b>Jump to an object</b>: Select it in the Hierarchy and press <b>F</b> (frame) with the mouse over the Scene view.

=H3 Tool shortcuts

<b>Q</b> hand (pan)  ·  <b>W</b> move  ·  <b>E</b> rotate  ·  <b>R</b> scale  ·  <b>T</b> rect. The coloured arrows that appear are called a <b>gizmo</b>: red is X, green is Y (up), blue is Z (forward).

=PAGE GameObjects and components
This is the single most important idea in Unity. <b>Everything in a scene is a GameObject</b>: a tree, a light, the camera, an invisible trigger, even an empty folder-like group. On its own a GameObject does nothing. It gets its abilities from <b>components</b> attached to it.

=BOX #F2B65C|Real-world link
Think of a GameObject as an empty Lego base plate and components as the bricks you clip on. Clip on a Mesh Renderer and it becomes visible. Clip on a Light and it glows. Clip on a Rigidbody and it falls. Clip on your own script and it does whatever you wrote.
=END

=H3 Transform: where things are

Unity measures in <b>units</b>, and the convention is <b>1 unit = 1 metre</b>. The player is about 2 units tall. <b>Position</b> is X (left/right), Y (up/down) and Z (forward/back). <b>Rotation</b> is in degrees around each axis. <b>Scale</b> of 1 means normal size; 2 means twice as big.

When you drag one object onto another in the Hierarchy, it becomes a <b>child</b>. A child moves, rotates and scales with its <b>parent</b>. Lantern Grove uses this a lot: <i>--- LANTERN GROVE ---</i> is a parent of <i>Environment</i>, <i>Path & Water</i>, <i>Landmark - Watchtower</i> and so on.

<b>Mouse</b>: Look around

<b>Space</b>: Jump

<b>G</b>: Open or close the step guide for the scene you're in

<b>Esc</b>: Release the mouse cursor so you can click the Editor again

=BOX #E58A7A|Watch out
<b>Changes made in Play mode are thrown away when you stop.</b> This catches out everyone. It is useful for experimenting (nothing is permanent) but if you find a setting you like, note the number down, stop Play mode, then type it in again. Many people set a Play mode tint (Edit › Preferences › Colors › Playmode tint) so it's obvious when they are playing.
=END

=PAGE Assets, materials and prefabs
• An <b>asset</b> is any file in the Project window: a model (.fbx), a texture (.png), a sound (.wav), a material, a script, a scene.

• A <b>scene</b> (.unity file) is one level or space. Each Learning Step is its own scene. <b>Save with Ctrl + S</b>, and save often.

• A <b>prefab</b> is a saved, reusable GameObject. Change the prefab and every copy in every scene updates. The particle effects in Step 08 are prefabs from <i>Assets/Zoo/VFX</i>.

• A <b>material</b> decides how a surface looks: colour, shininess, glow. Step 02 is all about them.

=BOX #7BC48A|Tip
Never rename or move files in Windows Explorer. Always do it inside Unity's Project window, otherwise Unity loses track of what is connected to what.
=END

=PAGE A first look at C#
Unity scripts are written in a language called <b>C#</b> (“C sharp”). A script becomes a component you can add to a GameObject. You don't need to be a programmer to follow these guides. Every script is explained line by line. Here is the shape of almost every Unity script:

=CODE Spinner.cs: a tiny script that spins any object
using UnityEngine;

// SPINNER: spins any object it is added to.
public class Spinner : MonoBehaviour
{
    // ---------- Settings you can change in the Inspector ----------

    // How fast to spin, in degrees per second.
    public float speed = 90f;


    // Start runs once, when Play begins.
    private void Start()
    {
        Debug.Log("Hello from " + gameObject.name);
    }


    // Update runs every frame (about 60 times a second).
    private void Update()
    {
        float degreesThisFrame = speed * Time.deltaTime;
        transform.Rotate(0f, degreesThisFrame, 0f);
    }
}
=END

<b>1</b>: <b>using UnityEngine;</b> lets the script use Unity's built-in tools (Transform, Debug, Time…).

<b>3</b>: A <b>comment</b>. Anything after <b>//</b> is a note for humans; Unity ignores it.

<b>4</b>: Declares a <b>class</b> called Spinner. The file must be called <b>Spinner.cs</b>, exactly the same name. <b>: MonoBehaviour</b> means “this can be attached to a GameObject as a component”.

<b>9</b>: A <b>public</b> variable. Unity shows it in the Inspector so you can change it without touching code. <b>float</b> means a number with decimals; the <b>f</b> after 90 marks it as a float.

<b>13–16</b>: <b>Start()</b> runs once at the beginning. <b>Debug.Log</b> prints a message to the Console. <b>private</b> means only this script can use the method; Unity can still call it.

<b>20–24</b>: <b>Update()</b> runs every frame. <b>Time.deltaTime</b> is the time since the last frame, so multiplying by it makes the spin the same speed on fast and slow computers (90 degrees per <i>second</i>, not per frame). Line 22 works the number out and stores it in a variable; line 23 uses it.

=BOX #7FC6E0|Good to know
<b>How every script in this project is laid out.</b> All the scripts you will meet follow the same simple pattern, so once you can read one you can read them all: a comment block at the top saying <i>what it does</i> and <i>how to use it</i>; a section of <b>public</b> settings you can change in the Inspector; a section of <b>private</b> variables only the script uses; then the methods, each with a comment above it. Everything is written out one step per line, with no shortcuts, so you can follow it from top to bottom.
=END

To try it: in the Project window right-click › Create › Scripting › MonoBehaviour Script (in older Unity versions: Create › C# Script), name it <b>Spinner</b>, double-click to open it, paste the code, save, then drag the script onto any object and press Play.

=BOX #7FC6E0|Good to know
C# is fussy. Capital letters matter (<b>Update</b> works, <b>update</b> silently does nothing), every statement ends with a semicolon <b>;</b> and every <b>{</b> needs a matching <b>}</b>. If the Console shows a red error after saving, double-click the error and it takes you to the line.
=END

=PAGE Greybox
=SUB Plan the space before you make it pretty: layout, scale, route and landmarks.

Everything in this scene is plain grey. That is on purpose. A <b>greybox</b> (also called a <b>blockout</b>) lets you judge whether a space works: is it the right size, can the player find their way, is there something interesting to walk towards? You answer those questions <i>before</i> spending hours on colours, lights and detail.

=IMG step01_hero|Step 01 from above the start clearing. No colour, flat lighting, default sky: only shape and layout.

• <b>You will learn:</b> what greyboxing is and why studios do it; how to read a layout; scale in Unity units; landmarks, sightlines and routes; how the Lantern Grove hierarchy is organised.

=PAGE The big idea
Imagine building a house. You would not choose wallpaper before checking the rooms are big enough and the doors are in sensible places. Level design works the same way. Game studios block out levels with simple grey shapes, play them, change them, and only then hand them to artists. Changing a grey cube takes seconds; changing a finished, textured, lit building takes days.

Grey also removes distractions. Without colour or dramatic lighting, you notice the things that actually matter to a player: <b>where am I, where can I go, and what do I want to reach?</b>

=BOX #F2B65C|Real-world link
Architects make cardboard models. Theatre designers make a “white card” model of the stage. Film-makers do a rough storyboard. A greybox is the game version: cheap, fast, and easy to throw away.
=END

=PAGE Key words
<b><color=#F2B65C>Greybox / blockout</color></b>: A rough version of a level made with simple untextured shapes, used to test layout and gameplay.

<b><color=#F2B65C>Scale</color></b>: How big things are compared to the player. In Unity, 1 unit = 1 metre and the player is about 2 units tall.

<b><color=#F2B65C>Landmark</color></b>: A big, distinctive object the player can see from far away and navigate by. Here: the watchtower.

<b><color=#F2B65C>Sightline</color></b>: What the player can see from a given spot. Good sightlines show the goal and hint at the route.

<b><color=#F2B65C>Route / critical path</color></b>: The main path through the level from start to goal.

<b><color=#F2B65C>Point of interest</color></b>: A smaller place worth visiting off the main path, e.g. the pond or the fairy ring.

<b><color=#F2B65C>Hierarchy</color></b>: The Unity window listing every object in the scene, grouped into parents and children.

=PAGE How Unity does it
There is no special “greybox mode” in Unity. A greybox is just ordinary GameObjects with plain grey materials. Lantern Grove uses three:

<b>LG_Greybox_Light</b>: Ground-level and path surfaces, so the walkable route reads clearly.

<b>LG_Greybox_Mid</b>: Most props, trees and rocks.

<b>LG_Greybox_Dark</b>: Contrast details such as the tower roof and posts.

The shapes themselves were made with <b>UModeler X</b>, a modelling tool that works inside Unity. The path, stream and pond are <b>parametric shapes</b> (the <i>UMXParametricShape</i> component), meaning you can change their width, curve and length with sliders instead of re-modelling them. Trees, rocks and animals come from the <b>Kenney</b> and <b>Quaternius</b> free asset packs in <i>Assets/3D Assets</i>, temporarily painted grey.

Lighting is deliberately boring: one Directional Light, flat ambient light and Unity's default sky. You'll replace all of that in Step 03.

=PAGE Reading the layout like a designer
=IMG step01_startview|The player's first view. The tower is visible straight ahead, framed by the gate and the path.

=H3 1. A landmark you can always see

From the very first frame the player can see the watchtower at the end of the path. That single sightline answers “where am I going?” without any text or arrows. Because it is tall, it stays visible above the trees as you walk.

=H3 2. A route that bends

The path winds rather than running dead straight. Bends hide and reveal things, which makes walking more interesting, and the stream and bridge create a natural <i>choke point</i> that keeps the player on track.

=H3 3. Rewards for exploring

The pond and fairy ring sit off to either side of the main path. They are optional, which makes finding them feel like a discovery. In Step 09 you'll see gems hidden at exactly these places.

=H3 4. Human scale

Door frames, steps, fences and benches all have real-world sizes the player instinctively knows. If the gate were 10 m tall the player would feel tiny; at 4.2 m it feels like a proper but approachable entrance. Always check new props against the player capsule (about 2 m).

=PAGE Build it yourself: a mini greybox
<color=#F2B65C><b>1.</b></color> Create a new scene: File › New Scene › <i>Basic (URP)</i>. Save it straight away as <b>MyGreybox</b>.

<color=#F2B65C><b>2.</b></color> Make a floor: GameObject › 3D Object › <b>Plane</b>. In the Inspector set its Scale to (5, 1, 5). A plane is 10 × 10 units, so this makes it 50 × 50 m.

<color=#F2B65C><b>3.</b></color> Make a grey material: in the Project window right-click › Create › <b>Material</b>, name it <b>Greybox_Mid</b>, and set its Base Map colour to a mid grey. Drag it onto the plane. Make a lighter and darker one too.

<color=#F2B65C><b>4.</b></color> Add a <b>Capsule</b> (GameObject › 3D Object › Capsule). It is 2 units tall, the same as a player. Use it as your “scale person” next to everything you build.

<color=#F2B65C><b>5.</b></color> Block out a goal: a tall Cube scaled to (4, 15, 4) at the far end of the floor. That's your landmark.

<color=#F2B65C><b>6.</b></color> Block out a route with flattened cubes (Scale Y = 0.1) using the light material, and add a few obstacles or a “bridge”.

<color=#F2B65C><b>7.</b></color> Add a player: open any Learning Step scene, select <b>Player (First Person)</b> in the Hierarchy and press Ctrl + C. Go back to your scene, press Ctrl + V, and delete the <b>Main Camera</b> your new scene came with (the player brings its own). Press Play, walk your route and time it.

<color=#F2B65C><b>8.</b></color> Group your objects under empty parents (GameObject › Create Empty) named <b>Route</b>, <b>Landmark</b> and <b>Obstacles</b>.

=BOX #7FC6E0|Good to know
Holding <b>V</b> while moving an object turns on vertex snapping, which makes lining shapes up much easier. Holding <b>Ctrl</b> while moving snaps to the grid.
=END

=PAGE Doing it with code (optional)
You'll rarely build a greybox in code, but this short script shows that a GameObject is just data you can create and change. Add it to any empty object and press Play to drop a row of grey “trees” along the Z axis.

=CODE GreyboxRow.cs
using UnityEngine;

// GREYBOX ROW: when Play starts, makes a row of grey "trees" (cylinders).
public class GreyboxRow : MonoBehaviour
{
    // ---------- Settings you can change in the Inspector ----------

    // Drag a grey material in here.
    public Material greyMaterial;

    // How many trees to make, and how far apart (in metres).
    public int count = 10;
    public float spacing = 4f;


    private void Start()
    {
        // Repeat the code inside the { } "count" times.
        // i counts 0, 1, 2 ... up to count - 1.
        for (int i = 0; i < count; i++)
        {
            // Make a new cylinder and give it a name.
            GameObject tree = GameObject.CreatePrimitive(PrimitiveType.Cylinder);
            tree.name = "Greybox Tree " + (i + 1);

            // Move it along the Z axis, a bit further each time.
            float z = i * spacing;
            tree.transform.position = new Vector3(6f, 2f, z);
            tree.transform.localScale = new Vector3(0.6f, 2f, 0.6f);

            // Give it the grey material.
            Renderer treeRenderer = tree.GetComponent<Renderer>();
            treeRenderer.material = greyMaterial;
        }
    }
}
=END

<b>9–13</b>: Public settings that appear in the Inspector: which material, how many, and how far apart.

<b>20</b>: A <b>for loop</b>: repeat the code inside <b>count</b> times, with <b>i</b> going 0, 1, 2…

<b>I fall through the floor in Play mode.</b><br><indent=4%>The floor needs a collider. Unity's Plane and Cube come with one; imported models may not (see Step 05).</indent>

<b>Objects are hard to place on the ground.</b><br><indent=4%>Select the object and press <b>End</b> to drop it onto the surface below, or hold Ctrl+Shift while dragging.</indent>
